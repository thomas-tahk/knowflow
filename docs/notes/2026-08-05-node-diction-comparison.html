Security-incident flows — node diction, before / after

Branch fix/sec-incident-content. Two rules, the second one learned during your review: a box is a label, not a sentence; and a description is one short line saying what the flow is — not a place to park overflow. The description renders as a single unwrapped line both in the app and in PNG/PDF export, so anything past ~90 characters is invisible. That means detail either fits in a node, rides an arrow, or is cut on purpose. Sections marked revised reflect your review; those went past diction into structure.

Shape now: InfoSec and CASA start side by side, both arrow into Confirm it is legitimate → Reset Password → IT's involvement is complete. Five nodes, same fan-in shape as Compromised Account. The P1 conditional is now a diamond instead of repeated text. It was stated twice in the trigger boxes and then contradicted by the layout, which put “Create a P1” on the main line for every path — so the diagram said always create a P1 while the words said sometimes. Now: three plain triggers → Reset Password → P1? → Yes creates the P1, No goes straight to Security Tasks; both meet again at Security Tasks. Criteria are stated once, in the diamond.
